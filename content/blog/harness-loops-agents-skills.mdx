The rise of Large Language Models has changed how software is built. Instead of
writing deterministic logic for every workflow, developers are increasingly
building systems that can reason, make decisions, and interact with tools.

As these systems grow more sophisticated, three concepts show up again and again:

- **Skills**
- **Agents**
- **Harness loops**

They're often used interchangeably, but they sit at different layers of an AI
architecture. Understanding what each one owns is essential for designing
reliable, scalable systems.

## The simple analogy

Imagine building a company.

- **Skills** are the employees who know how to do specific jobs.
- The **agent** is the manager who decides who should do what.
- The **harness loop** is the operating system that supervises everything —
  keeping work on track, handling failures, and deciding when the job is done.

Each layer builds on the one below it.

## Layer 1: Skills

A **skill** is a reusable capability. It performs one well-defined task with a
clear input and output.

Examples:

- Search the web
- Read a PDF
- Query a database
- Generate an image
- Send an email
- Summarize text
- Execute SQL
- Retrieve from a vector database

A skill generally does **not** make decisions. It performs work when asked.

```txt
Skill:
  Input:  "Summarize this PDF."
  Output: "A two-page summary."
```

Good skills are small, focused, reusable, and independently testable. Think of
them as APIs with a bit of intelligence baked in.

## Layer 2: Agents

An **agent** is responsible for reasoning. Instead of performing a single task,
it decides:

- What needs to be done
- Which skill to use
- In what order
- Whether more information is required

The agent has access to multiple skills and picks between them based on the
user's objective.

For example, if the user asks:

> "Research Tesla's latest earnings and create a presentation."

The agent might decide to:

1. Search the web
2. Read financial reports
3. Extract revenue numbers
4. Generate charts
5. Build a slide deck
6. Verify important facts

The agent orchestrates work rather than performing it directly. Its
responsibilities include planning, reasoning, tool selection, decision making,
memory, and handling unexpected situations.

## Layer 3: The harness loop

A **harness loop** is the runtime that controls the agent. It continuously:

1. Sends the current state to the LLM
2. Receives the next action
3. Executes the requested skill
4. Captures the result
5. Updates the conversation state
6. Repeats until the task is complete

A simplified version looks like this:

```python
while not finished:
    action = ask_llm(state)
    if action.is_tool_call:
        result = execute_tool(action)
        state = update_context(state, result)
    else:
        finished = True
```

The harness isn't intelligent by itself. It provides control, reliability,
safety, and execution management. Without a harness, an agent only produces
text. With one, it becomes an executable system.

## Responsibilities at a glance

| Responsibility        | Skill     | Agent     | Harness Loop |
| --------------------- | --------- | --------- | ------------ |
| Performs work         | Yes       | Sometimes | No           |
| Makes decisions       | No        | Yes       | No           |
| Calls tools           | No        | Yes       | Executes them|
| Controls execution    | No        | Partially | Yes          |
| Maintains runtime     | No        | No        | Yes          |
| Handles retries       | No        | No        | Yes          |
| Handles timeouts      | No        | No        | Yes          |
| Handles errors        | No        | Sometimes | Yes          |
| Stores execution state| No        | Partial   | Yes          |

## Why the harness matters

Many developers assume the LLM itself is the agent. In reality, the LLM is
usually just the reasoning engine. The harness provides the parts that make it
production-ready:

- Executing tool calls
- Maintaining conversation history
- Limiting the number of iterations
- Preventing infinite loops
- Applying safety policies
- Logging and metrics
- Recovering from failures
- Managing cost

Without a harness, there is no controlled execution environment — just a chat
completion in a for-loop.

## A real example: customer support AI

**Skills**

- Search documentation
- Read order information
- Issue refunds
- Create tickets
- Send emails

**Agent**

Decides whether the user needs a refund, whether a human should be involved,
whether documentation should be searched first, and whether the issue can be
resolved automatically.

**Harness loop**

Tracks conversation state, executes the selected skills, retries failed API
calls, logs every action, prevents endless reasoning loops, and closes the
interaction once the issue is resolved.

## The same pattern across frameworks

| Framework           | Skills   | Agent                 | Harness              |
| ------------------- | -------- | --------------------- | -------------------- |
| OpenAI Agents SDK   | Tools    | Agent                 | Runner               |
| LangGraph           | Nodes    | Agent                 | Graph Runtime        |
| AutoGen             | Tools    | Conversational Agents | Conversation Loop    |
| CrewAI              | Tools    | Crew Members          | Workflow Engine      |
| Semantic Kernel     | Plugins  | Planner               | Kernel Runtime       |

Terminology differs, but the architecture is remarkably consistent.

## Common misconceptions

**"An agent is just an LLM."** Not quite. An LLM provides reasoning; an agent
combines that reasoning with goals, memory, planning, and access to tools.

**"Skills are agents."** No. Skills are task-specific capabilities. They don't
plan or choose actions on their own.

**"The harness is part of the agent."** Usually not. The harness is the
execution environment that repeatedly invokes the agent, runs the requested
skills, updates state, and decides when to stop.

## Final thoughts

As AI systems evolve, separating **skills**, **agents**, and **harness loops**
leads to architectures that are easier to understand, maintain, and scale.

- **Skills** encapsulate specific capabilities.
- **Agents** decide how to achieve a goal by selecting and coordinating those
  capabilities.
- **Harness loops** provide the execution framework that manages state, invokes
  skills, handles failures, and knows when the task is done.

Design with these layers in mind and your AI applications will stay modular,
reliable, and adaptable as complexity grows.
